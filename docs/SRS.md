# ScreenAlarm — 소프트웨어 요구사항 명세 (SRS)

ISO/IEC/IEEE 29148:2018 구조를 따른다.

## 1. 개요

### 1.1 목적
macOS용 메뉴바 알람 앱의 요구사항을 정의한다. 알람이 울리면 소리 대신 화면 전체를 색상 블러로 덮는다. 사용자는 화면의 끄기 버튼을 직접 눌러야 알람을 해제할 수 있다.

### 1.2 범위
- 포함: 알람 생성·수정·삭제·켜기/끄기, 요일 반복, 알람별 블러 색상, 전체 화면 오버레이, 로그인 시 자동 실행, 로컬 저장.
- 제외(비목표): 소리·진동·알림 센터 알림, 스누즈, 잠자기 중 시스템 깨우기, 잠금 화면 위 표시, 강제 종료·앱 전환 차단(키오스크 모드), 클라우드 동기화.

### 1.3 용어
| 용어 | 정의 |
|------|------|
| 알람 | 시각(시:분), 내용, 반복 요일, 활성 여부, 블러 색상을 가진 항목 |
| 1회성 알람 | 반복 요일이 비어 있는 알람 |
| 오버레이 | 알람이 울릴 때 모든 화면을 덮는 창 |
| 검사 구간 | 스케줄러가 직전 검사 시각부터 현재 시각까지 확인하는 시간 범위 (from, to] |
| 농도 | 블러 위에 덮는 알람 색상의 불투명도(RGBA 의 a) |
| 유리 농도 범위 | 오버레이·미리보기에 쓰는 농도의 허용 범위 [0.10, 0.75] |
| 유리 타일 | 블러한 바탕화면 이미지 위에 알람 색상을 덮은 작은 둥근 사각형 |

## 2. 전체 설명

### 2.1 제품 관점
단독 실행 앱이다. 외부 네트워크와 통신하지 않는다. 데이터는 `~/Library/Application Support/ScreenAlarm/alarms.json` 에 저장한다.

### 2.2 사용자
Mac 사용자 1인. 관리자 권한이나 손쉬운 사용(Accessibility) 권한을 요구하지 않는다.

### 2.3 제약
- C-1 macOS 14 이상, Swift 6 / SwiftUI + AppKit.
- C-2 Xcode 없이 SwiftPM과 스크립트로 `.app` 번들을 빌드한다.
- C-3 앱이 실행 중이고 시스템이 깨어 있을 때만 알람이 동작한다.

### 2.4 가정
- A-1 사용자는 시스템 시계를 정상으로 유지한다.
- A-2 잠금 화면 위에는 서드파티 창을 띄울 수 없다(macOS 정책). 화면 잠금 중에 울린 알람은 잠금을 풀면 보인다.
- A-3 "투명도 줄이기"가 켜지면 macOS 는 `NSVisualEffectView` 블러를 불투명한 단색으로 그린다.

## 3. 요구사항

### 3.1 기능 요구사항 — 알람 관리
- **FR-1** 사용자는 알람을 추가할 수 있어야 한다. 기본값: 현재 시각 기준 다음 정각 분, 내용 "알람", 반복 없음, 활성, 색상 반투명 검정(RGBA 0,0,0,0.4).
- **FR-2** 사용자는 알람의 시각, 내용, 반복 요일(일~토 복수 선택), 블러 색상, 농도를 수정할 수 있어야 한다.
  - FR-2a 색상은 편집 화면 안의 프리셋 색 견본에서 한 번 눌러 고를 수 있어야 한다.
  - FR-2b 프리셋에 없는 색은 "다른 색" 버튼으로 시스템 색 패널을 열어 고를 수 있어야 한다. 색 패널은 편집 창 오른쪽 옆에 나타나야 하며, 색 패널에서는 농도를 바꾸지 않아야 한다.
  - FR-2c 농도는 슬라이더로 조정하며, 슬라이더 범위는 유리 농도 범위와 같아야 한다. 편집 화면에서 저장하면 농도를 유리 농도 범위로 잘라서 저장해야 한다.
  - FR-2d 시각은 시와 분을 각각 큰 숫자 칸에서 입력하거나, 위·아래 화살표 키와 스크롤로 1씩 바꿀 수 있어야 한다. 값은 범위 끝에서 반대쪽 끝으로 순환해야 한다(시 0~23, 분 0~59).
- **FR-3** 사용자는 알람을 삭제할 수 있어야 한다.
- **FR-4** 사용자는 알람을 개별로 켜거나 끌 수 있어야 한다.
- **FR-5** 알람 목록은 시각(시:분) 오름차순으로 표시해야 한다.
- **FR-6** 알람을 변경할 때마다 즉시 저장해야 한다. 앱을 다시 실행하면 저장된 알람을 복원해야 한다.
- **FR-7** 저장 파일이 없으면 빈 목록으로 시작해야 한다. 저장 파일을 해석할 수 없으면 원본을 `alarms.json.bak` 으로 옮기고 빈 목록으로 시작해야 한다.
- **FR-8** 오버레이와 미리보기는 저장된 농도를 유리 농도 범위로 잘라서(clamp) 써야 한다. 표시만으로는 저장된 값을 바꾸지 않아야 한다.

### 3.2 기능 요구사항 — 발화(트리거)
- **FR-10** 스케줄러는 1초 간격으로 검사 구간 (from, to] 을 확인해야 한다.
- **FR-11** 활성 알람의 발화 시각(해당 날짜의 시:분:00)이 검사 구간 안에 있고, 반복 요일이 비어 있거나 해당 날짜의 요일을 포함하면 그 알람은 발화해야 한다.
- **FR-12** 검사 구간 길이가 10초를 넘거나 0 이하이면(잠자기 복귀, 시계 변경) 그 구간에서는 아무 알람도 발화하지 않아야 한다. 즉 잠자기 중 놓친 알람은 건너뛴다.
- **FR-13** 1회성 알람은 발화 후 비활성으로 바뀌고 저장되어야 한다.
- **FR-14** 같은 구간에서 여러 알람이 발화하거나, 오버레이 표시 중 다른 알람이 발화하면, 큐에 넣고 현재 오버레이가 해제된 뒤 시각 순서대로 하나씩 표시해야 한다.

### 3.3 기능 요구사항 — 오버레이
- **FR-20** 발화하면 연결된 모든 화면을 덮는 창을 최상위 레벨로 띄워야 한다.
- **FR-21** 각 창은 배경을 블러 처리하고, 그 위에 알람의 색상을 FR-8 의 농도로 덮어야 한다. 시스템 설정의 "투명도 줄이기"가 꺼져 있으면 창 뒤의 실제 화면을 블러한다. 켜져 있으면(시스템 블러가 단색으로 바뀜) 해당 화면의 바탕화면 이미지를 앱이 직접 블러해 배경으로 쓴다. 바탕화면 이미지를 읽을 수 없으면 시스템 블러를 쓴다. 색상이 밝으면(상대 휘도 > 0.55) 밝은 블러와 어두운 글자를, 그렇지 않으면 어두운 블러와 밝은 글자를 써야 한다.
- **FR-22** 주 화면 중앙에 알람 시각, 알람 내용, "알람 끄기" 버튼을 표시해야 한다. 별도 카드 없이 유리 위에 바로 놓는다.
- **FR-23** 오버레이가 떠 있는 동안 오버레이 영역의 마우스 클릭과 키보드 입력은 아래 앱에 전달되지 않아야 한다.
- **FR-24** 오버레이는 "알람 끄기" 버튼을 마우스로 눌러야만 해제되어야 한다. Return, Esc, Space 등 키보드로는 해제되지 않아야 한다.
- **FR-25** 소리, 시스템 알림 등 다른 알림 수단을 쓰지 않아야 한다.

### 3.4 기능 요구사항 — 앱 셸
- **FR-30** 앱은 메뉴바 아이콘으로 상주하고 Dock에 표시하지 않아야 한다.
- **FR-31** 메뉴에는 다음 알람 시각, "알람 관리…", "로그인 시 실행" 토글, "종료"가 있어야 한다.
- **FR-32** "알람 관리…" 는 알람 목록과 편집 UI가 있는 창을 열어야 한다. 창이 이미 열려 있거나 다른 앱 창 뒤에 있어도, 창을 모든 일반 창의 맨 앞으로 가져오고 키 창으로 만들어야 한다.
- **FR-33** "로그인 시 실행" 토글은 `SMAppService.mainApp` 등록 상태를 바꾸고 현재 상태를 표시해야 한다.
- **FR-34** 앱을 처음 실행하면 로그인 시 실행을 자동으로 등록해야 한다. 이후 사용자가 토글로 끈 설정은 유지해야 한다.
- **FR-35** 등록 상태가 사용자 승인 필요(`requiresApproval`, 시스템 설정의 백그라운드 허용 꺼짐)이면 시스템 설정의 로그인 항목 화면을 열어야 한다. 메뉴에는 "로그인 시 실행 (승인 필요)"로 표시해야 한다.
- **FR-36** 앱은 관리 창을 닫아도 종료되지 않고 백그라운드(메뉴바)에서 계속 실행되어야 한다.
- **FR-37** 관리 창 상단에는 다음 알람의 시각, 내용, 남은 시간을 표시해야 한다. 활성 알람이 없으면 "예정된 알람 없음"을 표시해야 한다.
  - FR-37a 남은 시간 m(분)은 남은 초를 60으로 나눠 올림하고, 최소 1로 한다. 1일 = 1440분 기준으로 d일 h시간 n분으로 나눈다.
  - FR-37b 표기: d>0 이면 "d일 h시간 뒤"(h=0 이면 "d일 뒤"), h>0 이면 "h시간 n분 뒤"(n=0 이면 "h시간 뒤"), 그 밖에는 "n분 뒤".
- **FR-38** 알람 목록의 각 행은 유리 타일, 시각, 내용, 일~토 7칸 반복 표시, 켜기/끄기 스위치를 보여야 한다. 행에 마우스를 올리면 편집·삭제 버튼을 보여야 한다. 행을 선택하고 Delete 키를 누르면 알람을 삭제해야 한다. 행을 두 번 누르거나 편집 버튼을 누르면 편집 화면을 열어야 한다.
- **FR-39** 편집 화면 상단에는 현재 바탕화면 이미지를 블러하고 편집 중인 색상·농도를 덮은 미리보기를 보여야 한다. 미리보기에는 편집 중인 시각과 내용을 오버레이와 같은 배치로 보여야 한다. 바탕화면 이미지를 읽을 수 없으면 중립 회색 배경을 써야 한다. 화면 기록 권한을 요구하지 않아야 한다.

### 3.5 기능 요구사항 — 빌드·설치
- **FR-40** 저장소 루트에서 `make app` 을 실행하면 아이콘이 포함된 `build/ScreenAlarm.app` 을 만들어야 한다.
- **FR-41** `make install` 을 실행하면 빌드 후 실행 중인 ScreenAlarm 을 종료하고, `/Applications/ScreenAlarm.app` 을 새 번들로 교체한 뒤 다시 실행해야 한다.
- **FR-42** `make test` 를 실행하면 `AlarmCore` 테스트를 실행해야 한다. 실패가 있으면 0이 아닌 종료 코드로 끝나야 한다.
- **FR-43** 앱 아이콘은 저장소의 생성 스크립트로 만든 `Resources/AppIcon.icns` 를 쓴다. SF Symbols 등 사용이 제한된 자산을 쓰지 않아야 한다.

### 3.6 비기능 요구사항
- **NFR-1** 발화 지연은 예정 시각으로부터 2초 이내여야 한다(시스템이 깨어 있을 때).
- **NFR-2** 유휴 시 CPU 사용률은 평균 1% 미만이어야 한다.
- **NFR-3** 발화 판정·반복 계산·저장 로직은 UI와 분리된 모듈(`AlarmCore`)에 두고 자동 테스트로 검증해야 한다.

## 4. 검증

| 요구사항 | 방법 |
|----------|------|
| FR-5~FR-8, FR-11~FR-14, FR-21(휘도 판정), FR-2d(순환), FR-37a·b | `AlarmCore` 단위 테스트 (정상·경계·실패 사례) |
| FR-1~FR-4, FR-2a~c, FR-20~FR-25, FR-30~FR-39 | 수동 검사: 1분 뒤 알람을 만들어 동작 확인, 다른 앱을 앞에 둔 채 "알람 관리…" 실행 |
| NFR-1, NFR-2 | 수동 관찰 (활성 상태 보기) |
| FR-40~FR-43 | `make test`, `make install` 실행 후 `/Applications` 의 번들·아이콘·실행 상태 확인 |
